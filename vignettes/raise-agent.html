Using the RAISE Agent

RAISE is a Shiny application that uses an AI agent — called RAISE throughout this document — to help university lecturers design hypothetical studies and write statistics exam questions grounded in real regression output. This vignette explains every feature of the application.

Launching the app

library(RAISE)
run_raise()

You can also pass a session path directly so the app opens that session immediately on startup:

run_raise(session_path = "~/exams/2026-spring")

run_raise() requires the environment variable ANTHROPIC_API_KEY to be set. RAISE will not be able to reach the language model without it.

Sessions

All work in RAISE is stored in a session folder — a plain directory on your computer that you choose. The session folder is the only location RAISE can read from or write to; it never accesses files outside it.

Opening a session

Type a path into the Session text field in the sidebar and click Open, or use the Browse… button to pick a folder with a file browser. You can also press Enter after typing a path. Relative paths are resolved from R’s current working directory.

If the folder does not exist yet, RAISE creates it automatically together with four subdirectories:

<session>/
  materials/       <- uploaded lecture files
  studies/         <- one subfolder per study
  question_sets/   <- one JSON file per question set
  exports/         <- one subfolder per export

Session persistence

Every conversation turn is saved to <session>/chat.rds automatically after each exchange. When you reopen an existing session, the full conversation history is restored exactly as you left it — tool results, formatted output, and all — so RAISE can continue where you left off without losing context.

Clearing the chat

While a session is open, a Clear chat button appears below the Open button. Clicking it deletes chat.rds and starts a fresh conversation with RAISE. The studies, question sets, materials, and exports in the session folder are not affected — only the conversation history is reset. RAISE will greet you again and summarise the existing session content.

Materials

Lecture slides, reading excerpts, or any other reference text can be uploaded as materials. RAISE can read material files and use their content as the basis for exam questions.

Uploading a material

Use the Upload… button in the Materials section of the sidebar. Supported formats are PDF, Markdown (.md), and plain text (.txt). The file is copied to <session>/materials/ and immediately listed below the upload button.

Using materials in question generation

Once a file is uploaded, tell RAISE to use it:

“Generate five questions based on lecture3.pdf.”

RAISE will call load_material internally to read the file and then generate questions whose content is grounded in that text. RAISE can combine a lecture file with regression output from a study in the same set of questions.

Deleting a material

Each material entry in the sidebar has a Delete button. Clicking it once shows an inline “Delete? Yes / Cancel” confirmation. Clicking Yes permanently removes the file from materials/. You can also ask RAISE:

“Delete the file lecture3.pdf.”

RAISE will ask you to confirm before removing it.

Studies

A study is a fully designed and simulated statistical scenario: a hypothetical empirical study with defined variables, a correlation structure, regression coefficients, and the regression output produced by running lm() or glm() in R. Studies are the numerical foundation for exam questions — every number in a question must come from a study’s R output, never from the model’s imagination.

Each study is stored as a subfolder inside <session>/studies/ and progresses through four statuses as it is built:

Status Badge Meaning
description_saved 🟡 Title, context, and variables saved
correlations_set 🟠 Correlation matrix saved
coefficients_set 🔵 Regression coefficients saved
simulated 🟢 Dataset simulated; regression output available

Creating a study — the four-step workflow

RAISE guides you through study creation step by step. Start by telling RAISE what you want:

“Create a study about exam performance and study habits using linear regression.”

RAISE proceeds through four steps, presenting its proposal at each step and asking for your confirmation before saving anything to disk.

Step 1 — Description and variables. RAISE proposes a title, a context paragraph describing the hypothetical study, and a list of 3–6 independent variables with their types (continuous, binary, or categorical). It asks: “Does this look right, or would you like to change anything?” Confirm or request changes; RAISE then calls save_study.

Step 2 — Correlation matrix. RAISE proposes a correlation matrix for the independent variables, presented as a labelled table. It asks whether to save or adjust. On confirmation, save_correlations is called.

Step 3 — Regression coefficients. RAISE proposes coefficients that produce educationally interesting results — at least one significant and one non-significant predictor. It asks whether to save or adjust. On confirmation, save_coefficients is called.

Step 4 — R simulation. RAISE runs the simulation in R (lm() or glm()) and presents the full regression output, including odds ratios for logistic models. It asks: “Are you happy with these results, or would you like to adjust anything?” If you want changes, RAISE can redo any earlier step, automatically re-running all subsequent steps.

Study cards in the state panel

The right-hand column of the app shows the state panel, which lists all studies in the current session. Each study card displays the title, a colour-coded status badge, and the regression type. Two buttons are available:

  • Show — opens a modal with the full study design: variables (name, label, role, type, distribution), the correlation matrix, the coefficients table, and the regression output (once simulated). For logistic models the odds ratio table is shown as well.
  • Delete — clicking once shows an inline “Delete? Yes / Cancel” confirmation. Clicking Yes permanently deletes the study folder and all its simulation artefacts. Any question sets that still reference the deleted study will show a warning badge.

You can also ask RAISE to delete studies via chat:

“Delete the exam performance study.”

Question Sets

A question set is a named collection of exam questions saved as a JSON file in <session>/question_sets/. Each question set is linked to a study, a set of materials, or both. Questions come in two types:

  • Multiple choice (badge MC, blue) — at least four choices, one or more marked correct.
  • Numeric (badge #, grey) — a single numerical answer with a tolerance band.

Generating questions

Tell RAISE which source to use and how many questions you want:

“Write six questions based on the exam performance study.”

“Generate four questions from lecture3.pdf — two multiple choice and two numeric.”

RAISE reads the source (calling load_study_context or load_material as needed), drafts the questions in its response, and asks: “Shall I save these N questions, or would you like to adjust anything?” All numerical values are taken directly from the R output — RAISE never invents numbers.

After you confirm, RAISE calls save_question_set and the set appears immediately in the state panel.

Editing question sets

You can ask RAISE to revise a saved set at any point:

“Remove question 3 from the exam performance set.”

“Rewrite question 2 to focus on the confidence interval instead.”

“Add two more questions about model fit.”

RAISE uses remove_questions, update_questions, and add_questions respectively. It always loads the set first to look up the integer question IDs, and asks for your confirmation before modifying the file.

Question set cards in the state panel

Each question set card shows the topic name, the question count, and a row of type badges — one MC or # badge per question; hovering over a badge shows the first 90 characters of the question text. A warning label ([!] study deleted) appears if the linked study has been removed. Two buttons are available:

  • Show — opens a modal with the full question set: metadata (linked study, source materials, creation date, model) and every question with its choices or answer, tolerance, explanation, and exhibit text. Correct choices are highlighted in green.
  • Delete — two-step Yes / Cancel confirmation; permanently removes the JSON file.

Deleting a question set via RAISE:

“Delete the question set about regression diagnostics.”

Exporting Question Sets

Question sets can be exported to three formats for use in learning management systems:

Format Output Suitable for
PDF PDF file Printing / manual upload
TestVision ZIP archive TestVision LMS
Canvas ZIP archive Canvas LMS

Export requires LaTeX to be installed on your system for PDF output. TestVision and Canvas exports produce ZIP archives.

Exporting via the state panel

Check the checkbox on one or more question set cards. All checked sets are merged into a single export. Then:

  1. Optionally type a Prefix in the text field (e.g. midterm). If left empty, the prefix defaults to combined.
  2. Choose a format from the dropdown (PDF / TestVision / Canvas).
  3. Click Export selected.

A single question set and multiple sets are handled the same way — selecting multiple sets merges all their questions into one export file.

Exporting via RAISE

You can also ask RAISE to export directly from the chat:

“Export the exam performance question set as PDF.”

“Export all question sets together as a TestVision ZIP, using the prefix ‘midterm’.”

RAISE will ask you to confirm the destination format before proceeding, then call export_question_sets.

Export cards in the state panel

Completed exports appear in the Exports section of the state panel, listed newest first. Each export card shows the destination format, timestamp, question count, and filename. Three buttons are available:

  • Show — opens a modal with the export metadata and a preview of every question in the combined set.
  • Download — downloads the .pdf or .zip file directly to your browser.
  • Delete — two-step Yes / Cancel confirmation; permanently removes the export folder.

You can also list or delete exports via RAISE:

“Show me all past exports.”

“Delete the export from last week.”

Talking to RAISE

RAISE is a conversational agent. You do not need to use menus or buttons for most actions — describing what you want in plain language is sufficient. Examples:

You say What RAISE does
“Create a study about burnout in healthcare workers.” Starts the study creation workflow
“The correlation between age and tenure should be higher, around 0.6.” Regenerates and resaves the correlation matrix
“Simulate the study.” Calls simulate_study and shows the regression output
“Write 5 questions based on this study.” Loads study context and drafts questions
“Reword question 4 to be clearer.” Calls update_questions after loading question IDs
“Delete the burnout study.” Asks for confirmation, then calls delete_studies
“Export the burnout questions as PDF.” Asks for confirmation, then calls export_question_sets

RAISE always asks for your confirmation before writing, modifying, or deleting anything on disk.

Sandbox guarantee

RAISE reads and writes only within the active session folder. It cannot access files elsewhere on your system, make network requests (other than to the Claude API), or execute arbitrary code outside the controlled simulation pipeline.

Agent tool reference

The following tools are available to RAISE. They are called automatically during conversation — you do not invoke them directly.

Study creation tools

Tool Description
save_study Save study title, context, regression type, and variable list (step 1 of 4)
save_correlations Save the predictor correlation matrix (step 2 of 4)
save_coefficients Save regression coefficients (step 3 of 4)
simulate_study Run the R simulation and produce regression output (step 4 of 4)
delete_studies Delete one or more studies and all their artefacts

Question generation and editing tools

Tool Description
load_material Read a lecture file from materials/
load_study_context Load a study’s regression output and context
save_question_set Validate and save a complete question set to disk
remove_questions Remove specific questions from a set by integer ID
update_questions Replace specific questions in a set (full replacement by integer ID)
add_questions Append new questions to an existing set
delete_question_sets Delete one or more question sets
delete_materials Delete one or more material files from materials/

Discovery and export tools

Tool Description
list_studies List all studies in the session
list_materials List all files in materials/
list_question_sets List all question sets in the session
load_question_set Load the full content of a question set, including question IDs
list_exports List all past exports
export_question_sets Export one or more question sets to PDF, TestVision, or Canvas
delete_exports Delete one or more export folders
